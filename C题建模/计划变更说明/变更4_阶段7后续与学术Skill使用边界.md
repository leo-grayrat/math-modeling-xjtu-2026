# 计划变更 4：阶段 7 后续与学术 Skill 使用边界

## 为什么需要合并计划

阶段 7 已经完成，但后面还有三件已经提出、尚未处理的工作：判断阶段 7 的提高是否稳定、搜索统计和细胞领域的相关方法、评估 GitHub Projects 能否帮助管理进度。随后又安装了两套学术 Skill。如果只顾新工具，很容易忘记前面的工作；如果把每个 Skill 都完整跑一遍，又会在论文初稿之前耗费过多时间。

因此，新 Skill 只作为完成原计划的工具，不另开一条建模主线。进入第 8 步以前，先完成 Issue #22、#23 和 #24；其中只有定向搜索论文属于初稿前允许调用新学术 Skill 的例外。

## 合并后的执行顺序

1. 用最小 GitHub Project 显示 #22、#23 和新 Skill Sub-issue 的状态，Markdown 仍保存详细技术计划。
2. 在阶段 7 已固定的预测结果上补做按细胞配对的 Bootstrap 和置换检验。假设检验只说明提高是否稳定，不单凭 `p < 0.05` 决定采用模型。
3. 围绕多核学习、核化贝叶斯矩阵分解、通路或网络结构化方法和癌症依赖性冷启动预测，做一次有上限的定向文献搜索。
4. 综合统计结果和文献证据，写出下一阶段模型路线建议，然后停止并等待用户决定。
5. 用户同意路线后再继续第 8 步及后续建模，不根据 Skill 给出的新想法自动扩展工作。

## 初稿前怎样使用新 Skill

初稿前只使用与定向文献搜索直接有关的能力：

- 用 `academic-research-skills` 的三路扫描整理一篇论文为什么研究、怎样研究、得到什么，不启动完整 13-Agent 研究流水线；
- 用 `nature-academic-search` 做多源检索，并配合已有的 `academic-search` 和面向中文期刊的 `global-biblio-base`；
- 候选文献控制在 10 至 15 篇，只对其中 3 至 5 篇真正影响模型选择的论文做精读；
- 无法访问全文时直接记录 DOI 或 arXiv 编号，请用户协助获取，不重复更换接口；
- 搜索结果先形成路线建议，不能直接变成新的模型实验。

文献综述不会删掉。初稿中计划保留约半页至一页，重点比较已有方法、说明本题方法从哪里来以及现有方法没有解决什么。它不是文献名单，也不扩展成 PRISMA、Meta 分析或完整系统综述。

## 初稿前暂不使用的能力

初稿形成以前，不启动完整 `academic-pipeline`，也不使用完整同行评审、Nature 投稿材料、审稿回复、专利转换、每日文献推送等功能。`nature-statistics`、`nature-figure`、`nature-writing`、`nature-reviewer` 和 `academic-paper-reviewer` 留到初稿后集中评估，避免在阶段性结果尚未完成时反复润色和审查空架子。

## 停止条件

下面任一条件满足时，本轮文献搜索结束：已经找到能改变模型取舍的直接证据；候选文献达到 15 篇且核心方向已经覆盖；连续搜索只得到重复方法。完成统计检验和文献搜索后只提交路线建议，不进入下一轮建模。用户暂时没有回复不表示否决原计划，也不表示同意自动扩展。
